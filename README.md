# Inception

### Errors with layers.

Typed, location-aware error chains for Rust—built for stable APIs, useful diagnostics,
and safe defaults.

Most error libraries help you describe what failed. Inception also records **where each
meaningful layer was created**.

When a failure crosses a meaningful application boundary, wrap it in a new typed
Inception error. The result is a semantic trace that reads from the operation the
caller understands down through each semantic layer:

```text
checkout.reservation: The item could not be reserved.
    at src/checkout.rs:41:9
Caused by:
inventory.request: The inventory request failed.
    at src/inventory.rs:18:21
Caused by:
network.timeout: The inventory service timed out.
    at src/network.rs:73:19
```

No backtrace interpretation. No string matching. No accidental exposure of private
upstream messages.

## Three distinct error roles

Inception deliberately separates application errors, normal Rust errors, and the
adapter between them:

| Role | Implements | In the Inception trace | Standard source behavior |
| --- | --- | --- | --- |
| **Inception error** generated by `#[inception::error]` | `InceptionError` + `Error` | Yes, as a named semantic layer | Exposes its marked cause, if any |
| **Normal error** `E` | `Error` | No | Attached directly with `#[caused_by]` |
| **`Inceptioned<E>`** | `InceptionError` + `Error` | Yes, as the generic `inception.external` layer | Exposes the original `E` |

An **Inception error** represents meaning in your application: a stable code, a safe
description, structured context, and the location where that meaning was created.

A **normal error** remains an implementation-level source. Attach it with
`#[caused_by]` when it should be available to Rust's standard source chain but should
not become part of the semantic trace.

**`Inceptioned<E>` is the bridge.** It wraps a normal error, captures where it entered
the Inception world, and safely adds it to the semantic trace. The original value is
still available through `Error::source()`, but its message is never copied into the
Inception trace:

```text
Semantic trace                 Standard source chain

ConfigError                    ConfigError
└─ Inceptioned<io::Error>      └─ Inceptioned<io::Error>
   code: inception.external       └─ io::Error
   shows: type + location            retains: original message
```

The cause marker chooses the relationship:

```rust
#[caused_by(inception)] // another InceptionError, including Inceptioned<E>
source: DependencyError,

#[caused_by] // a normal Error; standard source chain only
source: Box<dyn std::error::Error + Send + Sync>,
```

## Why Inception?

- **Stable error identities** — every variant can expose a durable machine-readable
  code and a static, user-safe description.
- **Semantic creation traces** — every layer captures the exact source coordinate at
  which it gained meaning.
- **Typed causes** — nest Inception errors without erasing their types or breaking
  Rust's standard `Error::source()` chain.
- **Safe diagnostics by default** — generated `Display`, `Debug`, and traces do not
  reveal cause messages or context values.
- **Structured context** — ordinary fields become inspectable entries; sensitive
  fields can be marked `#[hide]`.
- **Explicit external error bridging** — keep a normal error source-only, or wrap it
  in `Inceptioned<E>` to add a safe generic trace layer.
- **A static error catalog** — generated metadata makes schema generation and rename
  checks straightforward.
- **`no_std` at the core** — the runtime uses `alloc`; Serde and `tracing` integrations
  are optional.

## Quick start

Add the repository dependency:

```toml
[dependencies]
inception = { git = "https://github.com/traumwohnung/inception" }
```

For a WebAssembly boundary, add the companion crate too:

```toml
[dependencies]
inception-wasm = { git = "https://github.com/traumwohnung/inception" }
```

Convert a typed error directly in a `Result` chain:

```rust,ignore
operation().map_err(inception_wasm::to_js_error)?;
```

The result is a JavaScript `Error` whose message is the safe Inception trace
message. Its `code`, static `description`, structured `location`, visible
`entries`, and nested Inception `cause` are attached as properties. Hidden
entries and ordinary external source messages never cross the boundary. This is
an in-memory FFI projection, not a serialization or wire protocol. Cause chains
are cycle-checked and limited to `inception_wasm::MAX_CAUSE_DEPTH` nested
errors; the last real error receives `causeTruncated` when projection stops.

Define one error type per semantic boundary:

```rust
#[inception::error]
enum NetworkError {
    #[code("network.timeout")]
    #[description("The inventory service timed out.")]
    Timeout,
}

#[inception::error]
enum InventoryError {
    #[code("inventory.request")]
    #[description("The inventory request failed.")]
    Request {
        #[caused_by(inception)]
        source: NetworkError,
    },
}

#[inception::error]
enum CheckoutError {
    #[code("checkout.reservation")]
    #[description("The item could not be reserved.")]
    Reservation {
        #[caused_by(inception)]
        source: InventoryError,
        item: String,
        attempt: u32,
        #[hide]
        service_token: String,
    },
}
```

Construct errors with the generated snake-case constructors. They capture the caller's
location automatically:

```rust
fn reserve(item: &str) -> Result<(), CheckoutError> {
    let network = NetworkError::timeout();
    let inventory = InventoryError::request(network);

    Err(CheckoutError::reservation(
        inventory,
        item.to_owned(),
        2,
        "secret-token".to_owned(),
    ))
}

let error = reserve("book-42").unwrap_err();

assert_eq!(error.code(), "checkout.reservation");
assert_eq!(error.description(), "The item could not be reserved.");

eprintln!("{}", error.trace());
```

Each non-cause field is available as structured context:

```rust
for entry in error.entries() {
    eprintln!("{}={}", entry.key(), entry.value());
}
```

```text
item=book-42
attempt=2
service_token=<hidden>
```

`#[hide]` replaces a value with `<hidden>` and does not require that value to
implement `Display`.

## Creating layers

Inception offers a small set of construction tools for common control-flow shapes.
Every one captures the semantic layer's creation site.

### Generated constructors

Unit, tuple, and struct variants receive snake-case constructors:

```rust
let timeout = NetworkError::timeout();
let checkout = CheckoutError::reservation(
    inventory,
    "book-42".to_owned(),
    1,
    token,
);
```

Named variants also receive builders:

```rust
let checkout = CheckoutError::reservation_builder()
    .source(inventory)
    .item("book-42".to_owned())
    .attempt(1)
    .service_token(token)
    .build()?;
```

Direct construction of the wrapper's variants is intentionally unavailable, so
creation-site capture cannot be skipped by accident.

### Enum-shaped construction

Use `locate!` when keeping enum-variant syntax is clearer:

```rust
let error = inception::locate!(InventoryError::Request {
    source: NetworkError::timeout(),
});
```

For an early return, `bail!` combines construction and `return Err(...)`:

```rust
fn fetch() -> Result<(), NetworkError> {
    inception::bail!(NetworkError::Timeout);
}
```

### `?` conversions

Mark a single nested cause with `#[from]` to generate `From` and add a fresh semantic
layer when `?` converts the error:

```rust
#[inception::error]
enum InventoryError {
    #[code("inventory.request")]
    #[description("The inventory request failed.")]
    Request {
        #[caused_by(inception)]
        #[from]
        source: NetworkError,
    },
}

fn load_inventory() -> Result<(), InventoryError> {
    fetch()?; // NetworkError becomes a new InventoryError layer here
    Ok(())
}
```

## Bridging normal Rust errors

Normal errors often contain valuable private diagnostics. Inception gives you two
deliberately different ways to attach them.

### Keep the error out of the semantic trace

Use plain `#[caused_by]` when the error should remain available through
`Error::source()` but should not become an Inception layer:

```rust
#[inception::error]
enum ConfigError {
    #[code("config.read")]
    #[description("The configuration could not be read.")]
    Read {
        #[caused_by]
        source: std::io::Error,
    },
}
```

Here the Inception trace contains only `config.read`. The `io::Error`, including its
original diagnostic message, remains available to code that explicitly walks the
standard source chain.

### Bridge the error into the semantic trace

Use `Inceptioned<E>` when the normal error should also appear as a safe, generic
Inception layer. The wrapper:

- captures the location where the normal error entered the Inception chain;
- identifies the layer with the stable code `inception.external`;
- shows the concrete error type, but not its message, in the semantic trace; and
- preserves the original `E` as its standard `Error::source()`.

```rust
#[inception::error]
enum ConfigError {
    #[code("config.read")]
    #[description("The configuration could not be read.")]
    Read {
        #[caused_by(inception)]
        source: inception::Inceptioned<std::io::Error>,
    },
}

fn read_config() -> Result<String, ConfigError> {
    std::fs::read_to_string("app.toml")
        .map_err(inception::locate_err!(ConfigError::Read))
}
```

`locate_err!` performs both steps at the call site:

```text
io::Error → Inceptioned<io::Error> → ConfigError
```

All three values remain connected through `Error::source()`. The semantic trace
contains `ConfigError` and `Inceptioned<io::Error>`, never the private `io::Error`
message.

For a standalone normal error, `locate!(error)` creates an `Inceptioned<E>` directly.
Use `bail_err!(error)` to create one and immediately return it.

## Codes, descriptions, and catalogs

Codes are for machines. Descriptions are safe static fallbacks for people.

```rust
#[inception::error]
enum PaymentError {
    #[code("payment.declined")]
    #[description("The payment was declined.")]
    Declined,

    #[code("payment.unavailable")]
    #[description("Payments are temporarily unavailable.")]
    Unavailable,
}
```

The macro generates a catalog alongside the error type:

```rust
for error in PaymentError::CATALOG {
    println!("{} — {}", error.code(), error.description());
}
```

When attributes are omitted, the defaults are `EnumName.VariantName` for the code and
`VariantName` for the description. Explicit values are recommended anywhere codes form
part of an API or observability contract.

## Integrations

### `tracing`

Enable the feature:

```toml
inception = {
    git = "https://github.com/traumwohnung/inception",
    features = ["tracing"],
}
```

Then emit a structured event:

```rust
inception::tracing::error!(error);
inception::tracing::warn!(error);
inception::tracing::log!(inception::tracing::Level::DEBUG, error);
```

Events include `error.code`, `error.description`, `error.trace`, and redacted
`error.context`.

### Serde

Enable `serde`, then opt an error type into generated serialization:

```toml
inception = {
    git = "https://github.com/traumwohnung/inception",
    features = ["serde"],
}
```

```rust
#[inception::error(serde)]
enum ApiError {
    #[code("api.unavailable")]
    Unavailable { request_id: String },
}
```

Serialized error values include their internal location and variant fields. Treat that
format as diagnostic data; project codes and safe descriptions into public API
responses explicitly.

## What belongs where?

Inception deliberately handles error **mechanics**, not application **policy**.

| Inception owns | Your application owns |
| --- | --- |
| Stable codes and safe descriptions | HTTP status and protocol mapping |
| Typed source relationships | Retry and recovery decisions |
| Creation locations and semantic traces | Logging and reporting policy |
| Structured, redactable context | Localization and user-facing copy |
| Static error catalogs | Public response schemas |

That separation keeps the error value useful across transports, executors, and
observability stacks without turning it into a policy container.

## Features

| Feature | Default | What it adds |
| --- | :---: | --- |
| `serde` | No | Serialization support and `#[inception::error(serde)]` |
| `tracing` | No | Structured `error!`, `warn!`, `info!`, and `log!` events |

The core crate is `#![no_std]` and requires an allocator.
